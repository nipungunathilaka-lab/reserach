# TC-08 Performance Evidence Provenance

## Original Problem
Historically, this repository contained synthetic throughput results to demonstrate the performance capabilities of the AI-Enhanced Secure File Transfer System before the final hardware integrations were completed. These results were stored in `backend/throughput_results_mock.csv` and generated by `backend/simulate_throughput.py`. As a result, the throughput data and resulting graph (`throughput_graph.png`) were mock artifacts, unfit for use as research evidence. 

## Resolution
The final performance evidence is derived ONLY from actual TC-08 runtime measurements. The historical mock simulation files have been safely archived to `tests/legacy_mock/` to prevent contamination. 

## Active Execution Path
The TC-08 tests (executed via `tc08_tc09_test.py`) use the actual active application endpoint (`POST /internal/crypto/encrypt`) to test the real secure file-processing path:

1. **Test Script**: `tc08_tc09_test.py` generates file sizes dynamically (1MB, 5MB, 10MB) and reads them from disk.
2. **Endpoint**: It sends a multipart form-data upload to `POST /internal/crypto/encrypt`.
3. **Controller/Service**: The API endpoint receives the stream and hashes the file to verify its integrity.
4. **Security Engine**: Files undergo malware scanning, Data Classification Scanning, Continuous AI Anomaly Monitoring, and Network Traffic Anomaly detection. (Note: For performance tests, anomalous time-of-day rejections are explicitly bypassed if `threat_score < 0.90`).
5. **PFCE/Crypto Processing**: `PFCEEngine.process_upload()` securely encapsulates the file, creating a ZIP package containing polymorphic fragments handled by `CryptoService`.
6. **Telemetry**: The wall-clock execution time is measured accurately using the monotonic OS clock primitive `time.perf_counter()`. CPU time is measured via `time.process_time()`.
7. **Result**: The endpoint calculates throughput and bandwidth programmatically and returns it as a JSON payload to the TC-08 script. The script collates these runs and writes to `tests/results/performance_telemetry_results.csv`.

## Measurement Methods
- **Elapsed Time**: `time.perf_counter()` (high-resolution wall-clock duration).
- **CPU Time**: `time.process_time()`.
- **File Size**: `file.size` or actually read bytes from the chunk loop. 
- **Throughput (MB/s)**: `file_size_MB / elapsed_time_seconds`.
- **Bandwidth (Mbps)**: `throughput_MB/s * 8`.

## Graph Generation
The final graph (`tests/results/graphs/tc08_throughput_graph.png`) is built EXCLUSIVELY from `tests/results/performance_telemetry_results.csv` using a deterministic Python script (`tests/generate_tc08_graph.py`). No fallback data or mock results are used in the final graph.

## Limitations
- **Single Host Benchmarking**: Tests are performed over `localhost`, eliminating real Wide Area Network (WAN) latency that would occur in a production deployment.
- **Application-Level Throughput vs Physical Bandwidth**: The recorded bandwidth is the effective application processing speed converted to Mbps. It is not a measurement of the physical Network Interface Card bandwidth capacity.
